# 📅 2026年06月03日

## 💭 当日念头

> 面试准备不是背答案，是把自己的经历翻译成对方想听的语言。

**核心念头：**
- 今天收到简历后，重新审视了之前出的63道面试题。有一半的问题放在他的银行对公背景和政府平台客户经验面前，回答方向完全变了——同样的知识点，有实战经验和没有实战经验，说出来的分量完全不同。
- 定制化比堆量更有价值。63道通用题+63道通用答案，不如1份结合简历的深度分析+重点策略。

**延伸思考：**
- 推日记到 GitHub 这件事折腾了两轮才跑通——第一次分支搞错了（master vs main），第二次 YAML 格式不对（模板里的冒号坑）。看起来是小事，但暴露了一个问题：手动操作容易漏细节，需要把流程固化。
- 修改了日记模板的 YAML 格式（去掉 date 后面的多余冒号、words 改为数字），这样以后自动生成的日记不会再出同样的问题。
- Vercel 部署权限问题：仓库设为公开就解决了。但如果有不想公开的内容，还是得走 Pro 方案或者用自己的账号推。

**今日有启发的事：**
1. 简历定制的价值远大于通用题库——同一个人在不同岗位背景下，同一道题的答法要完全换方向
2. 推送到GitHub经历两轮"试错→修复"才跑通，手动操作总有遗漏，流程化才是答案
3. Vercel免费版的部署权限限制可以通过公开仓库绕过，但私密场景需要付费方案

**改进点：**
- GitHub推送流程应该固化成一个自动化步骤，减少手动操作出错的可能
- 日记模板的YAML头部需要定期review，确保与博客系统的格式兼容
